# 2026-11-22 — Phone task lessons (sanitized, public)

Five automated phone calls today: three to a national eyewear retailer (insurance-coverage and lens-replacement questions) and two to an independent optometrist (appointment cancellation). No browser-based phone calls today. The retailer questions were answered; the cancellation was not completed — the office was closed and the call is rescheduled for the next business morning.

## Info-gathering calls

1. **Bundle all questions for one number into one call.** The retailer work took three calls because the first ended before the follow-up questions were asked. A single call with the full question list would have cost about half as much and needed only one menu navigation. Write the question list before dialing; don't end a call with known follow-ups unasked.
2. **Reuse the menu path that worked.** The third call reused the proven key-press path and reached a human in seconds. The second call explored a new branch for the same number and was transferred to an entirely different company. When re-calling a number, reuse the proven path; treat a new branch as an experiment, not the default.
3. **Never leave an automated-menu prompt unanswered.** Silence loops the prompt, then dumps the call to a transfer queue — in this case, the wrong queue. If the honest answer is "no," press it; if the branch is wrong, hang up and redial the known path.
4. **Verify the company name when a human answers.** The wrong-company greeting was the only signal the transfer had gone astray. The agent caught it and exited politely — keep that check on every transfer: if the greeting names a different company, apologize and end.
5. **Read-backs must name the specific facts, not the generic rule.** The first call's closing summary ("frames from the retailer only, not the customer's own frames") was confirmed by the rep while being wrong for this customer, whose frames are from that retailer. State the specific fact in the read-back ("his frames are from you, so they qualify") and let the rep confirm that.
6. **Hold the identifiers boundary — and report the limit honestly.** Personal identifiers were requested repeatedly across the calls and were not shared. The right outcome was "general answers only," reported as such rather than pushed past.

## Cancellation calls

7. **Check business hours before dialing.** Both calls to the optometrist hit a closed office on a Sunday. A 30-second hours check would have saved both dials. Hours-check is part of call prep, alongside the question list and the menu path.
8. **Don't re-dial a voicemail-only number the same day.** The second call, 16 minutes after the first, added nothing. One call establishes "closed / voicemail"; the next action is the scheduled callback, not a same-day retry.

## Outstanding (recurring across days)

- **Opener overlap still unfixed (observed 9/28, 10/10, 10/21, 11/22).** The greeting talks over the agent's first sentence every time; today it needed three restatements before a clean turn. This needs a call-config fix — shorter opener, a brief initial pause, or a tuned interruption threshold — not another note in a review file.

## Cost-per-task note

$1.97 across 5 calls (~14 minutes). The retailer questions should have been one call (~$1.04); the two voicemail calls should have been zero after a hours check. The waste this time was small in dollars but the pattern — split calls, unexplored branches, unanswered prompts, same-day redials — is exactly what compounds.
