# 2026-11-27 — Phone task lessons (sanitized, public)

One automated call today, to an optical retailer, asking them to release an insurance authorization so a frame benefit could be used at another store. The call succeeded and produced a definitive answer in one try. No browser-based phone tasks today.

## Insurance-authorization call

1. **Hold patience is a validated strength — keep it.** The representative put the agent on hold several times while pulling the record, about a minute and a half of waiting in total. The agent waited silently instead of filling the silence, and the representative came back with the answer. Silence is the correct hold behavior.
2. **Identifiers only when asked, one at a time.** The agent gave identifying details only when the representative requested them, one item per request, with authorization in hand. Never volunteer identifiers in the opener.
3. **Read back the next step, not just the answer.** The call's outcome was an instruction for someone else (call the insurer directly). The agent read that step back — "I can tell him to call the insurer directly to have the authorization cancelled, and that is all he needs to do?" — and got an explicit "Yes." For any call whose outcome is a next step for someone else, read the step back and get it confirmed in the other side's own words.
4. **If the other side says you're breaking up twice, offer to call back.** Mid-call the representative reported the agent's audio cutting in and out and nearly ended the call. The agent recovered by re-asking the confirmation question, but the rule should be: first "breaking up" → apologize and repeat the last sentence slowly; second "breaking up" → offer to call back immediately. A garbled confirmation is worse than a redial.
5. **Stop-and-listen applies to mid-call pauses too, not just the greeting.** Near the end of the call the agent tried to launch a follow-up question three times while the representative was still answering, and each attempt got talked over. This is the same overlap failure as speaking over a greeting, moved to the end of the call. The fix is the same discipline — let the other side finish the sentence before launching the next question — applied to every pause, not just the opening.
6. **Frame a reported premise as a question, not a fact.** The call opened by asserting an authorization existed and was blocking the benefit, based on another store's report — and that premise turned out to be wrong (the store had only done an exam and held nothing to cancel). Opening with "can you check whether you hold an authorization on this record?" gets the same check without anchoring the representative on a possibly false fact.
7. **A store that only did an exam holds nothing to release.** When a retailer says they never ordered or billed for materials, there is no authorization for them to cancel — the blocker, if any, sits with the insurer. The right next step is a call to the insurer, not a second call to the store.

## Outstanding (recurring across days)

- **Overlap: prompt fix validated at the greeting, config fix still open (observed 9/28, 10/10, 10/21, 11/22, 11/23, 11/24, 11/27).** The greeting-wait prompt fix keeps producing clean opens, but today's overlap cluster happened at the close of the call instead — same failure family, different moment. The config fix (shorter opener, a brief initial pause, or a tuned interruption threshold) is still outstanding, and the prompt guidance should now cover mid-call pauses explicitly, not just the greeting.
- **Audio break-up callback rule (new, observed 11/27).** Add "offer to call back after the second break-up report" to the standard call prompt.
